# My Thoughts - Bayangan yang Tertinggal Adventure Version

This file stores the creative direction notes and decisions from the user so they can be queried later.

## Core Goal

- Adapt the current horror game into a more interactive adventure-horror experience.
- Keep the original main story, but trim the total playtime to around 15 minutes.
- Maintain story coherence while adding more player interaction and a more enjoyable playthrough.

## Gameplay Direction

- Make the game feel more like an adventure game, not only a linear visual novel.
- Add more interaction through tools the player can pick up and use.
- Tools should affect choices, investigation, and endings.
- Missing assets can use placeholder images or grey objects until final assets are ready.

## Creative Direction

- Think from the perspective of a Horror Game Creative Director and Level Director.
- The story should remain focused and short, but each chapter should feel playable.
- The horror should come from understanding the situation, not only monster attacks.
- Malay dialogue should feel more natural and like day-to-day conversation.

## Chapter Structure

- The game should have chapter loading screens.
- Each chapter loading screen can be static.
- Each chapter card should introduce the scene and the characters involved in that chapter.

## Inventory And Notes

- Case notes should not always be visible on the main screen.
- Notes and inventory should be hidden under a button on the side.
- The side button should use an icon, preferably a backpack, instead of text like `KIT / NOTA`.
- Hovering over the backpack should reveal the inventory.
- The hover trigger should be small and close to the backpack icon, not a wide invisible area.
- Inventory should include items such as notebook, flashlight, phone camera, keris, kafan thread, old letter, tasbih, and salt.
- The notebook/case notes should be openable from the inventory.
- The notebook screen should look polished, with a textured paper/notebook overlay.
- The black square around the backpack icon should have rounded edges.

## Interaction Timing

- Timed action selections were too brief.
- Players need more time to read and choose.
- Action timers should be longer, especially when there are many choices.

## Character Placement

- Characters on the left and right should not hug the edges.
- Add padding on both sides so characters move closer toward the center.

## Ending Direction

- The final scene should not only show `Penamat`.
- Each ending should include wise/reflective words that explain the meaning of the outcome.
- The ending wise words should have a background image, not just a black screen.

## Ending Background Image Plan

- Use a static final grave/cemetery image as the main ending background.
- Base image idea: quiet cemetery at Batu Layar near dawn, one grave in the foreground, wet soil, loose white kafan cloth, faint trees or kampung shapes behind it.
- Good ending `DILEPASKAN`: calmer dawn light, loose kafan knot, tasbih near the grave, no monster silhouette, peaceful but sad.
- Bad ending `TIDAK FAHAM`: harsher dark red/brown tint, disturbed soil, keris mark, white cloth still tangled, silence feels wrong.
- Abandon ending `DITINGGALKAN`: road leaving the cemetery, grave in the background, white shape far behind, horror continues after MC leaves.
- Death ending `TERKUBUR BERSAMA`: ground-level grave view, dark soil close to camera, half-buried white cloth, claustrophobic framing.
- Production-simple option: create one strong grave-at-dawn background first, then use Ren'Py tint/overlay variations for each ending.

## Main Menu Background Idea

- Main menu background should show a freshly dug grave, called `liang lahad`.
- The image should let the player sneak a peek into the grave.
- Inside or near the grave, a white cloth should be partly visible, hinting at the pocong/kafan without fully revealing it.
- A flickering light should shine on the grave, creating an uneasy horror mood.
- The visual should feel like the story is already waiting inside the grave before the player starts.

## File And Asset Handling

- Old route files should be renamed with `-deprecated` behind the filename.
- Open-source assets can be used for inventory and notebook UI.
- Keep source/license information for downloaded assets.
- Placeholder icons or simple project-owned SVGs are acceptable until final art is available.
